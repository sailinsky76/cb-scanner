## 1. 先判「要不要开这一轮」，再动手

**默认答案是不开。** 这个项目 v5.9.1 之后连着五轮维护，其中最后三轮
（v5.9.4 / v5.9.5 / v5.9.6）改的分支**一个都没在实盘触发过** —— 三轮、三条断言、
报告里零个字符改变。原因写在 `STATE.md` 的「为什么改了六版还不收敛」那一节，
一句话是：**每一轮为了把话说清楚而新增的句子，就是下一轮 bug 的住址。**

所以先过 `STATE.md` 的「定稿标准」三条：

1. `check.sh` 七项全绿 + `diag_cbplan --selftest` 29 条
2. 实盘报告里每个数都能用报告里看得见的数复算出来
3. 报告里没有一句现在为假的话

**三条都满足 → 这一轮不该开。** 你如果发现了什么，判一下它会不会改变实盘报告的输出：
不会改的，写进 `STATE.md` 的「待触发清单」（改那一页就行，**不发版本、不加断言、不打包**）。

**该开轮的只有三种情况**：
- 接口挂了（某栏印出「取数异常」或整栏静默变空）
- 报告里有一句现在为假的话，或有一个数复算不出来
- 我明确要求改某个东西

  要写就配一条**按列/按类**钉的断言让机器去保证，否则它只是一句会腐烂的话

## 3. 真要改的时候，这几条纪律一条都不许松

我嫌的是没完没了的探针和文档，**不是嫌严谨**。报告要能信，靠的是这些：

- **不造数**：无出处的数一律不进报告。算不出来就不印，不许估、不许拟合
- **「没取到」不等于「没有」**：静默归零是本项目头号敌人。可以少印，不可以少说。
  接口挂了要在栏目级说出来，不许当成「今天没有」
- **同构的两处一起修**：v5.9.3→4→5→6 四轮全是「修了镜像的一边」。
  改一处之前先 grep 一遍同一个字段/同一列在别处怎么处理的
- **回放数值不许动**：`replay_20260808` / `replay_20260809` 是实盘复现
- **新分支要断言，且新断言必须先在旧代码上验红** —— 撞行为才算验红，
  撞 `ImportError`（「新函数还不存在」）不算
- **改完必须打包发回**：沙箱会销毁，留在工作目录里的改动等于没做
