## 1. 这个工具是什么，契约是什么

把四个**收益确定、规则即收益**的数据源接进来，每天出一份速览：谁今天要申购/缴款、
哪些配债值得抢权、哪些 LOF/QDII 出现折溢价、有哪些要约/吸并类事件套利线索。

**它不做统计检验、不预测、不造数。** 这一层的收益来自规则本身，不需要显著性。
这句话不是口号，它是下面每一条纪律的出处。

六个源：

| 模块 | 文件 | 主接口 |
|---|---|---|
| 转债获批公告（**批文已下、发行公告未出**，v5.9） | `scanner/sources/cb_approved.py` | `stock_zh_a_disclosure_report_cninfo()` + `bond_zh_cov()` |
| 可转债打新（申购/缴款/**上市**） | `scanner/sources/cb_ipo.py` | `bond_zh_cov()` |
| 转债退出提醒（**最后交易日**，v5.1） | `scanner/sources/cb_redeem.py` | `bond_cb_redeem_jsl()` |
| 配债一手党（含权量/沪深单位） | `scanner/sources/cb_allotment.py` | `bond_zh_cov()` + `stock_zh_a_hist()` |
| LOF/QDII 折溢价 | `scanner/sources/fund_premium.py` | 东财 ×2 / 新浪 / 同花顺 / 集思录 |
| 事件套利（线索发现） | `scanner/sources/event_arb.py` | `stock_zh_a_disclosure_report_cninfo()` |

## 2. 九条纪律：改代码前先读，破了就不是这个项目了

这些不是风格偏好，每一条背后都有一次踩过的坑。

1. **探明之前不写实现。** v3 那次栽的就是照着「接口应该有」去写，
   结果 `fund_etf_fund_daily_em` 根本不收录 LOF，修了几轮等于给枯井换绳子。
   凡是要新接口/新字段的，先写 `diag_*.py` 探针，**探针不产出机会条目、不接进 `scanner/`**。
2. **不造数。** 无出处的模型输出——合理价值、10 分制评分、预期涨幅、目标价——
   一律不进报告。整套工具的可信度建立在「每个数都能指回一个规则或一张表」上，
   印一个造出来的数，全栏跟着不可信。`selftest_fixes.py` 里钉了一份**定价词汇黑名单**，
   往上市提醒里加任何估值数会当场变红。
3. **印出来的数必须能被读者验算。** `verify_report.py` 五条不变量，`--mock` 与实盘每次运行都跑：
   ① 可投 × 净收益 = 预估 ② 组合合计 = 贪心复算 ③ 动作词方向 = 净收益符号
   ④ 同一条里不出现互相矛盾的指令 ⑤ 行内提示不超预算。
4. **提示预算：想加第 4 句，先删一句。** 常量在 `verify_report.py:213-215`——
   单句 ≤60 字、单条合计 ≤150 字、栏目说明 ≤160 字，超了 `--mock` 直接退出码 2。
   单句 60 字那道门堵的是「把三句用顿号缝成一句」的绕法。
5. **「没取到」不等于「开放 / 安全 / 没有」。** 这是本项目的头号敌人——静默归零。
   申赎状态没取到要单独成档且**不给它算净收益**；`场内规模` 整列缺要明说「未判定」；
   配债/上市 0 条要能分辨「真空窗」还是「列位移」。
6. **交易所规则不做成配置项。** 沪深最小配售单位（沪 1 手 1,000 元 / 深 1 张 100 元）
   写死在代码里。做成可调的等于给了改错的机会——那是规则，不是偏好。
7. **回放的数值不许动。** `replay_20260808/09` 复现的是实盘输出。改口径、改措辞可以，
   数值一旦变必须说清为什么，并同步回放。v4.6→v5.0 全程数值一字未改。
8. **方向性持仓不进这个工具。** 低价债轮动、溢价偏离轮动、小盘债池——要扛正股 beta、
   信用风险、市场整体估值波动，持有周期几周到一年。塞进一份叫「低容量套利」的日报
   会直接破坏这份报告的契约。（2024 年搜特/鸿达/蓝盾/岭南已实质违约，「最少收回 100 元面值」
   这个安全垫已被证伪，蓝盾退债最后交易日跌到 8.339 元。）
9. **每轮结束必须打包落盘。** 沙箱容器会销毁，上一次就因此丢过一整轮五个文件的改动，
   下一轮是照设计说明重做的。**改完 → 跑全套 → 打包 → 发出去**，不留在工作目录里过夜。

## 4. v5.0 / v5.1-rc 做了什么（4.1-4.4 = 阶段 1，4.5 = 阶段 2 离线那一半）

起因是复盘一篇讲配债套利的公众号文章。它的**策略**不能进这个工具（见纪律 8），
但它的**度量**（含权量）和**时点**（核准/公告/登记/缴款/上市/强赎那一串）
正好戳在两个空白上。三件事的数据全在 `bond_zh_cov` 那张表里，**一个接口都没加**。

### 4.1 上市日提醒（新增功能）

打新这条线上唯一要你自己做判断的那一天就是上市日（卖还是留），
而 v4 的工具把你推进仓位之后就再也不提这只债了。

- 窗口按**交易日**推（`list_window_trading_days`，默认 2）——写日历天的话周五跑盖不到周一。
- 申购侧那两道门（`min_rating` / `min_convert_value`）**不套在它身上**：
  那是「要不要申购」的判据，债已经在手里了。
- **只报时点，不报价格**（见纪律 2）。

### 4.2 最小配售单位分沪深（v5.0 唯一一处会给错数的口径修正）

v4.6.1 及以前两市统一按 1,000 元算，**深市转债的「需持股 / 占用市值」被放大了 10 倍**。
同一只标的（每股配售额 0.8、正股价 9.50）：

| | v4.6.1 | v5.0 |
|---|---|---|
| 深市 12x | 1,250 股 / 11,875 元 | **125 股 / 1,188 元** |
| 沪市 11x | 1,250 股 / 11,875 元 | 1,250 股 / 11,875 元（不变） |

列名跟着单位走（深市印 `配1张需持股`）。认不出代码前缀时按沪市高估，但会明说一句。
好消息是这一栏常年 0 条，所以还没害到人。

**还有一半写在脚注里没做进数值**：两市不足 1 个单位的零头都会进位，但进位是**竞争性**的
（沪市按尾数从大到小、深市按数量大小排序，直到总量配完）。所以「保证配满」和「博进位」
是两个数，后者事前不可知。工具只印前者——后者是赌注，不是可计算的量。

### 4.3 含权量：这是警告标签，不是功能增强

`含权量(%) = 每股配售额 ÷ 正股价`，配套印一句 `100 ÷ 含权量` =
**正股每跌 1%，需上市溢价 X% 才打平**（纯算术恒等式，不含定价假设，沪深通用）。

之所以说它是警告标签：**这一栏做的正是那篇文章自己说会亏钱的那件事**。
它靠「股权登记日」出条，而登记日只在发行公告**之后**才有值（通常只提前 2-3 个交易日）——
那时正股多半已经高开完了。真正的埋伏窗口在证监会核准到发行公告之间的 1-2 个月，
那段数据不在 `bond_zh_cov` 里（那是**已发行**转债的表），本工具**看不到**。
→ 这就是阶段 3 要解决的事。

### 4.4 「上市时间」列的取证（路线图里没有，实现时加的）

akshare 按**位置**命名 `bond_zh_cov` 那 70 多列，东财加一列就整体错位——
错位后申购/缴款照常出条（各自错到别的日期字段上，看着仍是日期），只有上市提醒天天 0 条，
和「本周没有新债上市」长得一模一样。语义不变量是现成的：**上市日必在申购日之后**。
大面积不成立报「列位移」；整列取不到单报一句；正常空窗只在本栏一条都没有时才说话。

### 4.5 转债退出提醒（v5.1，阶段 2 的离线那一半）

新增源 `cb_redeem.py`，接 `bond_cb_redeem_jsl()`。它补的是本工具最大的空白：
**管你进场，不管你离场**。

**刻意只读一列：最后交易日。** 那是 `diag_redeem.py` 实测坐实的字段
（`docs/probes/probe.txt` 存档在包里）。剩下 13 列一列不碰，等第二次探针的结论。

三档，缺一不可：

| 档 | 判据 | 紧急度 | 动作词 |
|---|---|---|---|
| ① 窗口内 | 最后交易日 ∈ [今天, 今天+N 交易日] | 按剩余交易日 | 「在此之前定好卖出／转股／持有」 |
| ② 已过 | 最后交易日 ∈ [今天-10, 今天) | 观察 | 「核对持仓里还有没有它」 |
| ③ 名单内但日期未取到 | 表里有行、日期为空 | 观察 | **不给动作词**，只陈述「未取到」 |

第 ③ 档是为春23 和应流留的：`docs/probes/probe.txt` 显示这两只**在表里有行、最后交易日是空的**。
只按「日期在窗口内」出条，它们会静默消失 —— 纪律 5 点名的头号敌人。

**这一版明确做不到的事，以及为什么不硬做：**

那张表把**强赎**和**自然到期摘牌**放在同一列里（嘉泽最后交易日 08-18 / 到期 08-24，
间隔 6 天，是到期形态；离到期还有几年的才是强赎形态 —— 而 probe2 实测这张表里
**一个远期样本都没有**，详见 §5.2），而两者的处置方向相反。
所以：动作词里**不给任何一只债贴「强赎」或「到期」的标签**，措辞一律用「最后交易日」。

但**栏目级那句「本栏不区分强赎与到期摘牌，两者处置方向相反」必须说**。
这两件事方向相反：给某只债下判断是越界，声明限制是义务。只做前一件的沉默不叫谨慎，
是把风险原样留给读者 —— 所以 `到期日` 也带年份一并印出来，让人拿两个原始日期自己看。

**三个实现期才发现的坑（都已钉进用例）：**

1. **`到期日` 不能按默认 `%m-%d` 印。** 年份正是区分到期和强赎的那个信息，
   吃掉年份之后「2029-01-25」显示成「01-25」，看着像到期日排在最后交易日前面。
2. **`强赎天计数` 不能进 metrics。** 它的取值形如 `20/15 | 30`，里面那个 ` | `
   正是 metrics 行的分隔符，塞进去会被读成两个指标（末尾冒出一个叫「30」的东西）。
   「原样透传」不允许替它换字符 → 换位置（挪进 `note`），不换值。
   同时它一次 `parse_date` 都不许调：`'12/15 | 30'` 会被啃成 `0001-12-15`。
3. **第 ③ 档必须有配额。** 这张表有多少行日期是空的当时还没探明（探针 2 的 Q4）。
   v5.1-rc 先按 `max_unknown: 20` 截断 + 总数照说处理，等 probe2 回答。
   → **probe2 答了：313/319（98%），于是这条改法整个被推翻，见 §5.5。**

### 5.3 探的过程中已经堵上的坑

1. **「不提前赎回」是「提前赎回」的子串，含义完全相反**——一个是「这次不赎、继续持有」，
   一个是「限期离场」。混错的代价不是少赚，是**照反方向操作**。
   `classify_title()` 里判定顺序就是为这个定的；`diag_redeem2.py` 的 `looks_forced()`
   同样先排否定写法，是同一个坑的第二次出现。
2. **并列写法会静悄悄给出错日期**：
   > 最后交易日、最后转股日**分别为**2026年8月18日、2026年8月20日

   从「最后转股日」往后找，先撞上的是 8月18日——那是前一个标签的值，**而且不会报错**。
   解析结果带 `ambiguous` 标记，三条判据命中任一条就标存疑。**不猜哪个对，只把疑点标出来**。
3. **`强赎天计数` 会被 `parse_date` 啃成日期**。原始值形如 `12/15 | 30`：
   按空格截断成 `12/15`，pandas 兜底读成「12 月 15 日」，年份缺省 0001。
   **只有首个数字 ≤12 时才中招**（`20/15 | 30` 返回 `None`）——
   恰好是倒计时刚开始的那批。→ 这一列当**不透明字符串**原样透传，一次 `parse_date` 都不调。
4. **`强赎天计数` 还会带 HTML**（probe2 新发现）。临近到期那批的取值是
   `临近到期 <span style="color:red;font-weight:bold;">!</span><br>2026-08-14 最后交易`。
   裸标签进 markdown 显示成尖括号，进 html **会真的生效**（红色加粗）——
   而报告里的字体权重是留给紧急度的。→ 透传前过一遍 `strip_html`：删标签，文本不动。
5. **齐翔2 第一次四张表全没对上，是匹配方式的问题不是数据的问题**。第一次探针按名称
   模糊匹配，而表里叫「齐翔转2」。→ 实现**按代码匹配**；probe2 的 Q3 已验证这条路
   （10 只里 9 只按代码回配成功，只有正帆是真的不在表里）。
6. **名单里有、日期为空的两只：春23、应流**。它们在 08-09 日报的已公告赎回栏里。
   → 第 ③ 档就是为它们留的；但这一档最后的形态被 probe2 改过一次，见 §5.5。
7. **「不在这张表里」的含义仍未定**。probe2 的 Q4 按代码求交给出了规模：
   本表 319 个代码里 317 个在 `bond_zh_cov`（1047 行）里，而**总表有 730 个代码不在本表里**。
   730 就是「看不到」的规模。**它不等于「没在赎回」**（纪律 5）——
   本栏的栏目级说明必须把这句话说出来，代码里已经钉住。

### 5.5 probe2 推翻的那一条：第 ③ 档不再逐条印

这是这一轮唯一的行为改动，也是**探针推翻实现**的一次实例，过程比结论有用。

v5.1-rc 的第 ③ 档判据是「表里有行、最后交易日为空 → 出条，超 `max_unknown: 20`
就按代码排序截断、总数照说」。当时不知道这一档会有多大。**probe2 测出来了：
319 行里带最后交易日的只有 6 行，其余 313 行为空（98%）。**

这一下把原做法的前提掀了：「空」在这张表里不是「这只债的日期丢了」，
而是「这只债还没有最后交易日」—— 313 行空值不含个体信息量。
把它离线复演一遍（probe2 的真实 6 行 + 按实测比例铺开的 313 行），后果是两条同时出现：

- 印出来的 20 条是**代码最小那批噪音**，天天占版面；
- 这一档本来要救的春23(113667)/应流(113697)，**恰好被截在配额外面**。

既灌了噪音，又没救到人，还让读者以为这一档有覆盖 —— **比不印更糟**。

改法（`unknown_ratio_gate`，默认 0.5）：空占比 ≥ 阈值且是大表时，这一档**一条都不逐行印**，
改在栏目级说一句 ——

> 本栏 319 行里只有 6 行带最后交易日，其余 313 行该列为空 —— 空不等于「没在赎回」，
> 本栏对这 313 只给不出时点，手里有债以公告为准

少印可以，少说不可以；但「说」的形式不必是逐条占位。
**空是少数派时判据不变**（那才是异常）：照旧截断展示 + 报总数。
`unknown_ratio_gate: 1.0` 可关掉这条口子，回到 v5.1-rc 的行为，用例里钉了这条回退路径。

都在 `config.yaml` 的 `cb_redeem:` 一节，现在的值是我拍的：

#### Q4 单独立一问：先钉单位，钉不住就不许算

拟发行规模从巨潮拿到的是「万元」还是「元」还是「亿元」，列名里没写。
**猜错就是 10⁴ 倍的含权量。** v4.6.1 深市配售单位放大 10 倍，就是一个没对过的单位假设，
害了整整一栏。所以 Q4 拿已发行的债和 `bond_zh_cov` 的「发行规模（亿元）」对一次比值，
中位数落在 1 / 1e4 / 1e8 哪个附近就是哪个单位；**对不出来就退出码 1，Q5 直接跳过**。

#### 含权量的口径：恒等式 + 一个多出来的假设

    含权量 = 每股配售额 ÷ 正股价，而 每股配售额 = 拟发行规模 ÷ 总股本
    ⇒ 含权量 = 拟发行规模 ÷ 总市值

约掉的是同一个正股价，所以它和 `cb_allotment` 那一栏印的是**同一个数**，
只是把「等发行公告才有的每股配售额」换成了「预案里就有的拟发行规模」。
但它**多带一个假设**：原股东可优先配售比例 100%。真写实现时这句话必须进栏目级说明。

**验收标准现成**：复现 08-09 那份日报的四只 ——
**四方科技 23%、丰茂股份 16%、满坤科技 14%、千红制药 11%**。

**不是任何东西的计数**，是「30 × 这次翻了多少页」。底下的唯一集合每次都是同一个 3000。

`page_bound_note()` 原来印的「可能是**下界**而非全量」把两件事混成一句，方向还取错了一半：

- 当「取回了多少条**不同**的公告」看 → 3300 / 8880 **偏大**（真值 3000），是**上界**
- 当「窗口里**实际**有多少条」看 → 3000 本身就是封顶值，只是个**下限**

→ **已改**：那一行只说「这个数不是计数，是 30 × 翻的页数」，**不贴方向**；
方向只许贴在**唯一数**上。用例第 5 条从「必须说下界」**翻成「不许说下界/上界」**。
重复行的**具体形态**（到底哪几页在重）没量，所以那一层没写进措辞。

**② 连带证伪了 §6.4 自己的一个结论。**
§6.4 写的是「少掉的整页全出自那一路，分子比分母更吃亏，22/133 不稳」。

所以 **22/133 跨轮是稳的**（probe4/5/6 三次都是 133 / 22）。但它**仍然不能当总体比例用**,

**截掉那部分有没有偏也没量过**。→ 探针里那段措辞已按这个改；§6.4 原文就地划掉并指回这里。

## 9. 环境与已知的坑

- **沙箱连不上东财/巨潮/集思录。** 实盘模式会在「数据源健康」里如实报错但不崩。
  实盘和所有 `diag_*.py` 都必须在你自己的机器/服务器上跑。
  这也是当初建议把这套放进 Claude Code 边写边跑的原因。
- **`ConnectionError: RemoteDisconnected` 不必慌**，多半是东财对连打全市场大表的限流，
  过几分钟重跑即可——已成功的表还在 15 分钟缓存里。
- **改 README 时用 `str_replace` 吞掉下一节标题，已经发生过两次**（v4.6.1 那节、v4.5 那节）。
  改完务必 `grep -c "^## " README.md` 对一下章节数（**当前应为 19**）。
- **阶段 3 的设计说明不在 README 里**，在本文 §6 + `diag_cbplan.py` 的文件头注释里。
  v5.3 这一轮 README **一个字节没动**（所以还是 19 章）——
  阶段 3 到现在一行实现都没写，README 讲的是「每一处为什么这么设计」，
  没有实现就没有该写进去的东西。等真要写实现时，再照阶段 2 的先例给它一节。
- **Windows 上 `py -3.11 x.py > out.txt` 时 stdout 走 locale 编码（简中机器上是 GBK）**，
  而 `✓ / ✗ / ⚠` 在 GBK 里编不出来 —— 第一次成功取数就 `UnicodeEncodeError` 崩掉。
  **不重定向时控制台是 UTF-8，所以一直没事，一重定向就炸。**
  **已经搬成代码了**：`diag_common.py` 里的 `apply_stream_fix()`，
  六个探针一律 `from diag_common import apply_stream_fix` 然后在**任何 print 之前**调一次，
  `diag_cbplan.py --selftest` 第 25 条逐个文件钉住这件事。**新写探针照抄那两行。**
  兜底策略**必须是** `backslashreplace`，**不许用** `replace` ——
  后者会把 `✓` 和 `✗` 一起变成 `?`，而这俩是「取到 / 没取到」的唯一区分（纪律 5）。
  *（这一条 v5.5 只写成了一句「别的探针还没修，留意」，一轮之后 `diag_sources.py`
  就照原样崩了一次、白费一次跑动 —— 见 §6.7 ④。**能变成代码的就别只写成文字。**）*
- **`--exit-zero`** 可强制返回 0，挂 cron 时按需要用。
  正常退出码：0 = 四个源都完整取到；1 = 报告已生成但有源残缺；2 = 全失败，报告没参考价值。
