## 为什么改了六版还不收敛 —— 记一次，别再重新讨论

**输出三个版本前就收敛了。** `--mock` 报告正文的 md5 在 v5.9.4 / v5.9.5 / v5.9.6
上**逐字节相同**（`0b5638ccbec4fbb1130c4fbd82af2b91`），08-13 的实盘报告里
这三轮改的分支一个都没触发。三轮、三条断言、报告里**零个字符**改变。

所以不收敛的不是代码，是**停止规则**。两个原因：

**① 最近三轮的 bug 是上一轮的修复造出来的。**
v5.9.3 给评级门加了一句「另有 N 只评级低于阈值」→ v5.9.4 发现这句话断言了代码判不了的事
（`AA+sti`）→ v5.9.5 发现这句话把空值当成取值 → v5.9.6 发现同一列在另一个文件里也这样。
这不是在清积压，是一个**反馈环**：DoD 是「报告里每句话都为真」，而每一轮为了把话说清楚
都会新增句子，**新句子就是下一个 bug 的住址**。

**② 「看看有没有问题」这个问法，在 9000 行代码上永远返回「有」。**
任何认真的复核都能无限找下去，而找到的绝大多数在永不执行的分支里。
加上收尾规矩里那句「新分支照旧要断言」，**每个发现都被自动升级成一个版本** ——
于是发版节奏由复核的产出率决定，而不是由产品的需要决定。
以前这个项目缺的就是「真但永不触发」这个抽屉，所以什么都掉进发布流程里。

**两个结构性的修法都已经落在这一页上**：上面的「定稿标准」（三条，只看输出）
和「待触发清单」（真但不触发的，改这一页，不发版本）。

## 附：v5.9.6 修的一处（存档）—— 上一轮宣布「唯一」的那处，第二处就在隔壁

这一轮的出处不是实盘，也不是源码复核 —— 是**上一轮自己写下的那句话**。

```python

```

`cb_allotment` 和 `cb_ipo` 读的是**同一张表（`bond_zh_cov`）的同一列** ——

每一轮的教训都写着「两处都修才对称，只修一处下一轮还会再翻出来」，
而 v5.9.5 一边抄这句话、一边又只修了一处 —— 还多加了一句「唯一」把它锁死。

### 改法：借过来，不抄第二份

## 附：v5.9.3 那一轮修的四处（存档，非本轮）

### ① `check.sh` 每跑一次，就删掉当天的实盘报告

`run.py` 写盘只看日期戳，**不区分实盘 / mock / 回溯**：

```python

```

而 `check.sh` 的第六项正是 `run.py --mock --format console markdown html`。
于是「跑一次自检」＝「用编的数覆盖当天的真报告」。这一栏和前几轮修的都不同类：
**它不是报告印错，是把用来核对报告的东西销毁了** —— 而且销毁得毫无痕迹，
文件名、时间戳、格式全都对得上。

`--date` 是同一个口子且方向更别扭：它拿**今天**的实时数据、盖上过去的日期戳，
再覆盖那一天的归档 —— 回溯测试销毁被回溯那天的凭据。

**改法**：判据只有一条 —— 这次产出**能不能代表 stamp 那天的真实市场**。

| 跑法 | 能否代表 | 写到哪 |
|---|---|---|
| 实盘，且日期就是系统当天 | 能 | `reports/scan_{stamp}.md`（**行为一字未变**） |
| `--mock` | 不能（数据是编的） | `reports/_scratch/scan_{stamp}.mock.md` |
| `--date` 指到别的日子 | 不能（数据是今天的） | `reports/_scratch/scan_{stamp}.asof.md` |

后两种还会在日志里说一句自己不是实盘产出。`_scratch/` 不进包（同 `.cache`）。

### ② 打新的两道门仍然静默，而 0 条那句话会**说反**

v5.9.2 修的是「门写成 `continue`、跳掉整行」，方向对；但门本身**一条都不数**。


窗口里明明有两只。**同一轮里 `fund_premium` 的三个开关都补了计数并照说，
打新这两个漏了** —— 补话的那一轮只看了折溢价那个文件。

还有更隐蔽的一层：阈值是 `_RATING_RANK.get(min_rating, 99)`，**认不出就是 99**，

### ① `cb_ipo` 申购侧的门写成了 `continue`，跳的是**整行**

```python
if within(申购日, t, look_end):
    if not _rating_ok(rating, min_rating):
        continue          # ← 跳到 DataFrame 的下一行，不是跳过这一个提醒
```

于是同一只债的**缴款提醒和上市提醒被一起吃掉**。而 `cb_ipo.py` 里明写着

```
min_rating=''    → 2 条: ['今日顶格申购', '缴款提醒：确保账户留足现金']
min_rating='AA'  → 0 条: []                    ← 缴款提醒静默消失
```

**为什么现在才暴露**：默认 `min_rating: ""` / `min_convert_value: 0`，
两个 `continue` 永远不触发。只要你哪天开了任一道门就会踩，
而丢掉的是这条线唯一的硬性风险（连续 3 次不缴款拉黑半年）。

**改法**：门只关**申购**这一条，其余两条照走。

### ② 交易日历越界的方向**写反了**，而且今年 12 月就会撞上

`utils.py` 原来写着「回落跳周末（把节假日当交易日 → **窗口偏长**，宁可多提醒一天）」。
方向是反的：把节假日当成交易日 → 更快数满 n 个 → 终点**更早** → 窗口**更短**。

更要紧的是**它不需要「日历拿不到」才触发**。`TradeCalendar.is_trading` 对超出
覆盖范围的日期走同一条回落，而新浪日历只排到当年年底 —— 包里那份实测
8797 行、最晚 **2026-12-31**。拿这份真实日历算：

```
2026-12-30  缴款窗口 +2 交易日 → 算出 2027-01-01（元旦当天）   实际应为 01-04
2026-12-29  退出窗口 +5 交易日 → 算出 2027-01-05              实际应为 01-06
2026-12-28  退出窗口 +5 交易日 → 算出 2027-01-04              实际应为 01-05
```

退出提醒每年年底都会少一个交易日，而**漏掉一只 = 那只债卖不掉了** ——
这正是 `cb_redeem` 整栏为之存在的那件事。全程只有一行 `log.info`，栏目级一个字不说。

**改法**：新增 `trading_window_end(d, n, cal)` → `(终点, 是否被日历担保)`。
两个函数分工写死，别再混：

- `shift_trading_days(d, n)` 回答「**第 n 个交易日是哪天**」—— 一个事实，
  语义里不该掺安全边际。**这一版一个字没改**。
- `trading_window_end(d, n)` 回答「**要盖住未来 n 个交易日，窗口该开到哪天**」——
  一个判断，方向上必须偏保守。没担保时多开 3 个工作日，并把 `False` 一起返回，
  由源在**栏目级**说出来（多出来的那几条要有解释）。

**边际只在「日历在、但够不着」时补**，整个日历都没取到时一天都不多开。
两种降级不是一回事：日历整个没取到时，日志和栏目级已经各说了一遍、整份报告
本来就是降级件，而且那种机器多半一直没网，天天多开会让**窗口宽度取决于网络状态**，
自检也跟着不可复现（`_run_source` 走的就是 `mock=False` 这条路，
第一版改法当场把 `test_listing_reminder_is_a_date_not_a_price` 打红了）。
日历在、只是排到年底 —— 报告看起来完全健康，那才是静默的那一种。

### ③ `cb_approved` 空代码把不同公司并成一条

```python
code = _norm_code(r.get("代码", "")) or "未取到"
```
